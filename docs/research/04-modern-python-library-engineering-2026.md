# Modern Python library engineering for an AI-agent-native async chat-bot framework (state of the art, Sep 2026)

Research date: 2026-09-02. Primary sources only (PEPs, python.org, official docs, GitHub READMEs/changelogs). Items marked **[unverified]** could not be confirmed against a primary source during this session.

## 1. Python versions

**Release status (devguide, as of 2026-09-02):**

| Version | Status | First release | EOL |
|---|---|---|---|
| 3.16 (`main`) | feature | 2027-10-06 (planned) | 2032-10 |
| 3.15 | prerelease — **rc2 shipped 2026-09-01, final 2026-10-01** (PEP 790) | 2026-10-01 | 2031-10 |
| 3.14 | bugfix (3.14.7 = 2026-08-05; last binary bugfix 3.14.14 on 2027-10-05) | 2025-10-07 | 2030-10 |
| 3.13 | bugfix (bugfix ends ~2026-10 when 3.15 ships, then security-only) | 2024-10-07 | 2029-10 |
| 3.12 | **security-only** (no more binary bugfix releases) | 2023-10-02 | 2028-10 |
| 3.11 / 3.10 | security-only | — | 2027-10 / **2026-10** |

Practical reading: on 2026-10-01 the "two bugfix branches" become 3.14 + 3.15; 3.13 drops to security-only; 3.10 dies.

**Free-threading (PEP 703 → PEP 779).** 3.13: experimental, separate `python3.13t` executable, `sys._is_gil_enabled()`. 3.14: "officially supported" (PEP 779 phase II), specializing interpreter enabled in the FT build, single-thread penalty 5–10 %, `-X context_aware_warnings`, `thread_inherit_context` (both default on in FT builds — relevant for `contextvars`-based request context in an async library). 3.15 adds **PEP 803 stable ABI `abi3t`** for FT extensions. py-free-threading.github.io guidance for pure-Python libs: avoid module-level mutable global state and unsynchronized dict caches, add multithreaded tests; pure Python stays "as thread-safe as under the GIL". Not yet the default build in 3.15.

**Typing PEPs by version.**
- 3.12: PEP 695 `class Router[T]:` syntax + `type` aliases; PEP 698 `@typing.override`.
- 3.13: PEP 696 TypeVar defaults (`class Bot[StateT = dict[str, object]]`), PEP 742 `TypeIs`, PEP 705 `ReadOnly` TypedDict, PEP 702 `warnings.deprecated`.
- 3.14: **PEP 649/749 deferred annotations** (new `annotationlib`, `Format.VALUE/FORWARDREF/STRING`) — libraries introspecting hints at runtime (dependency injection by annotation, pydantic-style) must use `annotationlib.get_annotations(..., format=Format.FORWARDREF)` / `typing.get_type_hints`; PEP 750 t-strings (`string.templatelib.Template`, useful for injection-safe logging/SQL/HTML builders); PEP 758 `except A, B:`; PEP 765 `SyntaxWarning` for `return` in `finally`.
- 3.15: PEP 747 `TypeForm`, PEP 728 closed `TypedDict` (`closed=True`, `extra_items`), PEP 800 `@disjoint_base`; also PEP 810 `lazy import`, PEP 814 `frozendict`, PEP 661 `sentinel`, PEP 798 `[*x for x in xs]`, UTF-8 default mode, `datetime.utcnow()` **removed**.

**asyncio by version.** 3.13: `Queue.shutdown()` + `QueueShutDown`, TaskGroup cancellation-collision fixes (preserves `cancelling()` count; `create_task` on inactive group closes the coroutine), `as_completed` yields the original tasks, `create_task(**kwargs)` forwarded to Task, `Server.close_clients()/abort_clients()`, `StreamReader.readuntil(tuple)`. 3.12 already had `eager_task_factory`/`create_eager_task_factory` (used by `TaskGroup` in 3.13+). 3.14: `python -m asyncio ps <pid>` / `pstree <pid>`, `asyncio.capture_call_graph()`/`print_call_graph()`, `concurrent.interpreters` (PEP 734) + `InterpreterPoolExecutor`. 3.15: `TaskGroup.cancel()`, Tachyon sampling profiler with `--async-aware` (PEP 799).

**Recommendation for our library:** `requires-python = ">=3.13"` for a *new* framework released after Oct 2026 — 3.12 is security-only already, 3.13 is the oldest branch that gives `TypeIs`, TypeVar defaults, `ReadOnly`, `warnings.deprecated`, `Queue.shutdown` and free-threading test builds; test 3.13/3.14/3.15 (+ a `3.14t` job), write code that is annotation-lazy-safe (never read `__annotations__` directly), and drop 3.13 when 3.16 ships (rolling "two bugfix branches" policy). Do **not** go 3.14-only yet: Debian 13 / Ubuntu 26.04 / uv-managed CPython make 3.13 ubiquitous, and 3.14-only buys nothing a library needs at runtime.

## 2. Type checkers 2026

- **ty (Astral)** — latest **0.0.77 (2026-09-01)**; releases every few days, still `0.0.x`, **no GA/1.0/beta label anywhere in the releases or docs**. Docs position it as production-backed ("10x–100x faster than mypy and Pyright" on home-assistant), Rust, LSP included. Strictness is a rule table: `[tool.ty.rules] all = "error"` sets every rule to error, per-rule `error|warn|ignore`, `[tool.ty.overrides]` per-file, `[tool.ty.terminal] error-on-warning` (default true), `[tool.ty.environment] python-version/python-platform`. Recent releases add opt-in "unsound assignment/return/yield" rules, Pydantic field validation, pytest fixture resolution, PEP 723 scripts. Gap pattern: still fast-moving inference (recursion guards, protocol handling, TypeVar inference fixes every release) — pin exact `ty==0.0.x` in dev group and bump deliberately.
- **pyrefly (Meta)** — **1.0.0 released**, Rust, Instagram's default checker (20 MLoC), explicitly *not* semver ("minor updates may introduce breaking changes", mitigated by `pyrefly suppress`), monthly minors, reads mypy/pyright config (`pyrefly init`), built-in Pydantic/Django/pytest support.
- **pyright** — 1.1.41x line (release dates from the releases page came back garbled in this session — **[unverified]** exact date of 1.1.412); implements PEP 800 `@disjoint_base`, PEP 728 closed TypedDict promoted from experimental, default target Python bumped 3.13→3.14 in 1.1.407, PEP 736 support removed after SC rejection. Still the reference implementation for the typing spec's conformance suite.
- **mypy** — changelog lists **2.3 as current** (2.0 happened in the 2025-26 cycle). 2.2: PEP 728 closed TypedDict, full PEP 696 defaults, PEP 747 `TypeForm` stabilised, honours `__new__` return type. 2.3: free-threading memory-safety work in mypyc, `librt.threading.Lock` (2–4x faster in compiled code), runtime-read-only `Final` attributes in native classes.

**What top libraries run (pattern, Sep 2026):** *two* checkers — one fast daily (ty or pyright) + mypy for the mypyc/plugin ecosystem — is common in libraries that ship a mypy plugin or compile with mypyc (pydantic, attrs). Pure-Python libs increasingly run **ty + pyright** in CI and drop mypy. The typing spec conformance suite makes divergences documentable; a library should pick *one* checker as the source of truth for `# type: ignore[code]` comments and treat the other as advisory (or use `# pyright: ignore` / `# ty: ignore[rule]` specific comments so ignores do not collide).

**Typing tests.** (a) `typing.assert_type(expr, T)` in ordinary `.py` files under `tests/typing/` (or `typesafety/`) that are *type-checked* in CI but never imported by pytest — works with every checker, zero plugins; (b) `pytest-mypy-plugins` YAML cases (`main:`, `out:` with `reveal_type`, `parametrized`, `regex`) — **mypy-only**, use when you ship a mypy plugin; (c) `pyright --verifytypes <pkg>` for completeness of the public surface (report `py.typed` coverage %). The official `typing.python.org` best-practices page covers style (Protocol/`Sequence` params, concrete returns, `object` over `Any`) but not testing — test conventions come from the libraries themselves.

**Recommendation for our library:** ship `py.typed`; make **ty `all="error"`** the primary gate (it is what our bots already run) and add **pyright `strict` + `--verifytypes`** as a second CI job; keep mypy out unless we adopt mypyc; add `tests/typing/*.py` with `assert_type` checked by both.


## 3. Lint and architecture enforcement

- **ruff 0.16.5 (2026-08-27)**. **0.16.0 (2026-07-23)** is the big one: default rule set grew from 59 to **413** rules (18 opinionated pycodestyle/pyflakes rules dropped from defaults: E401, E402, E70x, E71x, E721, E731, E74x, F403/F405/F406, F722); new `# ruff: ignore[F401]` suppression comments (end-of-line or preceding line) alongside `noqa`; **formats Python code blocks in Markdown by default**; `format --check` shows diffs with GitHub/GitLab annotation formats; preview "rules without codes and category selectors". `select = ["ALL"]` is still supported and neither deprecated nor discouraged in the notes, but with 413 defaults the practical 2026 idiom is `extend-select` a short list on top of defaults plus explicit `ignore`, and `preview = true` only in a non-blocking job. Ruff has not declared 1.0.
- **wemake-python-styleguide 1.x** (latest 1.8.0 "The Slop Slayer"): 1.0 re-based WPS on ruff — dropped all bundled flake8 plugins and >50 codes duplicated by ruff; official invocation is `ruff format && ruff check && flake8 --select=WPS .`. Worth it only if you want its complexity/"Jones" metrics; it is still flake8-hosted (slow) — optional.
- **import-linter** contract types: `forbidden`, `protected` (allow-list importers), `layers`, `independence`, `acyclic siblings`, custom. Config lives in `.importlinter` (INI) or `[tool.importlinter]` in `pyproject.toml`; a `layers` contract is the direct encoding of "handlers → services → repositories → clients".
- **slotscheck**: verifies `__slots__` inheritance/overlap/duplicates, can *require* slots (`require-subclass`, `require-superclass`); CLI `slotscheck -m pkg`, pre-commit hook, `[tool.slotscheck]`. Relevant for a hot-path event framework that slots its `Context`/`Event` classes.
- **pyproject-fmt v2.29.3**: canonical key ordering, classifier generation from `requires-python`, dependency sorting; `[tool.pyproject-fmt]`; pre-commit hook.
- **typos** (crate-ci): corrections-list approach (known-typo → fix) so it "can safely run unassisted" with very low false positives; config `_typos.toml` (`[default]`, `[files]`, `[type.*]`), GitHub Action + pre-commit, `--format json`. **codespell** is dictionary-based and noisier — pick typos.
- **zizmor**: static analysis for GitHub Actions/Dependabot/pre-commit: template injection, unpinned `uses:`, credential persistence (`artipacked`), excessive permissions, impostor commits. No GitLab CI support documented.
- **bandit / semgrep**: still the two security linters; ruff's `S` (flake8-bandit) rules cover most bandit checks natively, so a separate bandit run is redundant when `S` is selected; semgrep for custom taint rules (webhook payload → shell/URL).
- **deptry**: DEP001 missing, DEP002 unused, DEP003 transitive, DEP004 misplaced dev deps; supports PEP 621/uv/PDM/Poetry, `[tool.deptry]`. Run it in the lint job to keep `extras` honest.
- **`uv audit`** exists in uv 0.12.x ("Audit the project's dependencies"; details in §4). **pip-audit 2.10.x** audits environments, requirements and `pylock.*.toml` (`--locked .`), uses PyPI advisory DB or `--vulnerability-service osv`, `--strict`, `--fix` — no `uv.lock` input, so with uv either use `uv audit` or `uv export --format pylock.toml`.

**Recommendation for our library:** ruff ≥0.16 with defaults + `extend-select` (ANN, ASYNC, S, PL, RUF, FURB, PERF, TRY, EM, LOG, G, T20) and `per-file-ignores` for tests; `import-linter` layers contract; `slotscheck`; `pyproject-fmt`, `typos`, `zizmor`, `deptry`, `uv audit` in pre-commit/CI; skip WPS, bandit, codespell.


## 4. Build and release

- **uv 0.12.x**; build backend declared as `requires = ["uv_build>=0.12.9,<0.13"]`, `build-backend = "uv_build"`. Docs insist on the **upper bound**. `uv_build` supports **pure-Python only** (no extension modules, no build scripts/hooks), `module-name`, `module-root` (default `src/`), `namespace`, `source-include/exclude`, `wheel-exclude`, `data`, stub packages. Docs say use **hatchling** when "build scripts or a more flexible project layout are required" (also when you need dynamic version from VCS via `hatch-vcs`, or mypyc — see below). uv also now ships `uv format` (ruff-backed) and `uv audit`.
- **Lockfile gate:** `uv lock --check` (alias of `--locked` semantics: "assert that uv.lock will remain unchanged") in CI; `--frozen` to install exactly what is locked without checking. Use `uv lock --check` in the lint job, `uv sync --frozen` in test jobs.
- **PEP 735 dependency groups**: `[dependency-groups] dev=[...] lint=[...]`, `{include-group = "x"}` nesting, `[tool.uv] default-groups = ["dev"]` or `"all"`, `--group/--only-group/--no-default-groups`, per-group `requires-python` via `[tool.uv.dependency-groups]`. Groups are **not published**; extras (`[project.optional-dependencies]`) are. Mutually exclusive extras must be declared in `[tool.uv] conflicts`.
- **`uv version`**: `--bump major|minor|patch|stable|alpha|beta|rc|post|dev`, `--dry-run`; `uv build --no-sources` before publish; `uv publish` needs **no credentials under Trusted Publishing** and auto-uploads `.publish.attestation` files (PEP 740) found in `dist/`.
- **PyPI Trusted Publishing**: OIDC token from the CI provider exchanged for a 15-minute project-scoped token; configure publisher (owner/repo/workflow file/environment) on PyPI, "pending publisher" for not-yet-created projects; job needs `permissions: id-token: write` and should use a protected GitHub `environment: pypi`. Providers listed by PyPI: GitHub Actions, GitLab CI/CD, Google Cloud, ActiveState — **[unverified in this session]** whether the list grew in 2026.
- **mypyc for an asyncio lib — mostly no.** Documented costs: compiled functions/classes are immutable (no monkeypatching → tests must inject via protocols, which we do anyway), `inspect.signature`/`ismethod` break, no `pdb` breakpoints, no stack-overflow check, pickling needs `@mypyc_attr(serializable=True)`, and it locks you to mypy as the checker plus a platform wheel matrix (no `uv_build`). Pros: 2–5x on CPU-bound pure-Python paths (routing filter evaluation could qualify). For an I/O-bound bot framework the wins are marginal and the DX cost for agent-driven development (no monkeypatching, opaque tracebacks) is high. **[unverified]** current mypyc async-generator coverage.
- **Changelog tooling**: (a) **towncrier 25.8** — news *fragments* `changes/<issue>.<type>.md` (`feature|bugfix|doc|removal|misc`, `+orphan`), `towncrier create`, `towncrier build --version X`, `towncrier check` in CI (fails PR without fragment) — best for multi-contributor/agent PRs because the human-readable entry is written *with* the change and reviewed; (b) **git-cliff 2.14** — generates from Conventional Commits, `cliff.toml`, `--bump`/`--bumped-version`, GitHub/GitLab CI recipes, recommends squash-merge; (c) **commitizen** — `cz check` commit-msg hook, `cz bump` (semver from commits, `version_provider = "uv"`/`pep621`), changelog. Conventional Commits + squash merge + git-cliff gives zero-friction automation; towncrier gives curated notes. Combine: Conventional Commits enforced by `cz check`, fragments by towncrier, version by `uv version --bump`.
- **Deprecation**: `@warnings.deprecated("msg", category=DeprecationWarning, stacklevel=1)` (3.13; `typing_extensions ≥4.5` backport) — runtime warning on call/instantiation, `__deprecated__` attr, and type checkers flag every use. Pair with a documented policy: deprecate in minor N, remove in N+2 minors, listed in a "removal" towncrier fragment.

**Recommendation for our library:** `uv_build` (pure Python, src layout), PEP 735 groups (`dev`, `lint`, `docs`, `typing`), `uv lock --check` + `uv sync --frozen` in CI, Trusted Publishing with attestations from a protected `pypi` environment, semver 0.x→1.0 with `uv version --bump`, Conventional Commits (cz check) + towncrier fragments, `warnings.deprecated` everywhere; no mypyc.


## 5. Docs

- **mkdocs-material 9.7.7 (2026-07-17)** — **in maintenance mode since 9.7.0**: the squidfunk team moved to *Zensical* (their next-gen SSG) and all former Insiders features became free. Still the most complete MkDocs theme (search, tabs, tags, privacy plugin, breadcrumbs) and the one most agent tools know how to write for; 9.7.7 fixed a DOM-XSS in search suggestions — pin ≥9.7.7. Expect a migration to Zensical or a successor in 1–2 years.
- **Sphinx + shibuya + MyST** — shibuya is a modern responsive theme (dark mode, radix colours, landing/3-column layouts) used by Sentry SDKs, Authlib, Emscripten; pairs with `myst-parser` for Markdown. **sphinx-autodoc2** is the static (no-import, `TYPE_CHECKING`-safe) autodoc for MyST — still describes itself as "just released, feedback welcome", i.e. small maintainer base.
- **API reference**: `mkdocstrings-python` (Griffe, static AST, Google/NumPy/Sphinx docstrings, auto cross-refs via inventories, inherited members, source toggles). Griffe also powers **API-breakage checks** (`griffe check`) — useful as a semver gate.
- **Executable docs**: pytest built-in `--doctest-glob="*.md"` (doctest syntax only); **sybil 10.1** (pytest `pytest_collect_file`, parsers for doctest/codeblock/MyST/Markdown, `skip`/`capture`/namespace-clearing — the most complete); **mktestdocs** (`check_md_file(fpath, memory=True)`, `check_docstring`, custom executors); or the FastAPI pattern **`docs_src/` + `tests/`** where every snippet is a real importable module imported by tests and included in docs via `--8<--` snippets. For an async library the `docs_src/` pattern is best: snippets are type-checked by ty/pyright and run under pytest-asyncio without doctest hacks.
- **llms.txt** (Jeremy Howard, 2024-09-03, last modified 2026-08-10): `/llms.txt` = H1 name, blockquote summary, free text, H2 "file lists" of `[name](url): note`, optional `## Optional` section; `llms-full.txt` convention for the whole corpus; per-page `.md` alternates advertised with `rel="alternate" type="text/markdown"`. Generators: **mkdocs-llmstxt** (`llmstxt` plugin; `sections`, `full_output`, `autoclean`, `preprocess`; requires `site_url`; marked maintenance mode) and **sphinx-llms-txt** (`llms.txt` + `llms-full.txt`, parallel-safe). Claude Code docs and agentskills.io themselves publish `/llms.txt` — the convention is now expected of libraries.
- **Context7** (`context7.json` at repo root: `projectTitle`, `description`, `folders`, `excludeFolders`, `excludeFiles`, `rules`, `previousVersions`; submit via context7.com/docs/adding-libraries; MCP tools `resolve-library-id` → `query-docs`). **DeepWiki** (Cognition) auto-generates a wiki + MCP for public GitHub repos; no maintainer config file — quality depends on README/docs clarity.
- **Versioned docs**: **mike** (`mike deploy --push --update-aliases 1.2 latest`, `mike set-default latest`, `versions.json`; `extra.version.provider: mike` in mkdocs-material). ReadTheDocs remains the zero-ops alternative for Sphinx or MkDocs.

**Recommendation for our library:** MkDocs + mkdocs-material 9.7.x + mkdocstrings-python + `docs_src/` snippets tested by pytest and type-checked; ship `llms.txt`/`llms-full.txt` via mkdocs-llmstxt (plus a hand-curated compact `llms.txt` like aiommbot's), `context7.json`, and mike-versioned deploys; keep a watch item to evaluate Zensical.


## 6. AI-agent-native repo layout

**Agent Skills (open spec, agentskills.io; Anthropic-authored, adopted by Codex/ChatGPT, Claude Code, Cursor, others).** A skill = directory with `SKILL.md` (YAML frontmatter + Markdown) and optional `scripts/`, `references/`, `assets/`. Frontmatter: `name` (required, 1–64 chars, `[a-z0-9-]`, no leading/trailing/double hyphen, **must equal the directory name**), `description` (required, ≤1024 chars, "what it does *and when to use it*", keyword-rich), optional `license`, `compatibility` (≤500 chars), `metadata` (string map), `allowed-tools` (experimental). Progressive disclosure: ~100 tokens of metadata at startup → `SKILL.md` body (<5000 tokens, <500 lines) on activation → referenced files on demand; keep references one level deep. Validate with `skills-ref validate ./my-skill`.

- **Discovery paths:** Codex/ChatGPT: `$CWD/.agents/skills`, `$REPO_ROOT/.agents/skills`, `~/.agents/skills`, `/etc/codex/skills`; invoked explicitly with `$skill-name` or implicitly by description match (`policy.allow_implicit_invocation`). Optional `agents/openai.yaml` inside the skill: `interface: {display_name, short_description, icon_small, icon_large, brand_color, default_prompt}`, `policy: {allow_implicit_invocation}`, `dependencies: tools: [{type: mcp, ...}]`. Claude Code: `.claude/skills/<name>/SKILL.md` (project, root + nested per-package, loaded when files there are touched), `~/.claude/skills`, plugin `skills/`; Claude-specific frontmatter beyond the spec: `disable-model-invocation`, `user-invocable`, `disallowed-tools`, `model`, `context: fork` + `agent`, `argument-hint`, `${CLAUDE_SKILL_DIR}` substitution. **Portable practice:** author skills once under `.agents/skills/` (spec-only frontmatter) and add `.claude/skills/<name>` → symlink, or a `.claude-plugin/plugin.json` + `marketplace.json` that points `skills` at `.agents/skills`. django-modern-rest does exactly this (`.agents/skills/dmr/SKILL.md`), and Astral's ruff `CONTRIBUTING.md` has a "Local skills for Codex or Claude" section.
- **`AGENTS.md`** (agents.md, now stewarded by the Agentic AI Foundation under the Linux Foundation; >60k repos, 25+ tools incl. Codex, Cursor, Copilot, Zed, Jules, Aider): plain Markdown, no schema, root + nested (nearest wins); content = build/test commands, conventions, PR rules, security notes. **Claude Code reads `CLAUDE.md`, not `AGENTS.md`** — official guidance is `CLAUDE.md` containing `@AGENTS.md` plus Claude-specific lines, or a symlink. Claude Code also supports `.claude/rules/*.md` with `paths:` frontmatter (path-scoped rules), `CLAUDE.local.md` (gitignored), <200-line target, and `/init` imports Cursor/Copilot rules.
- **Cursor**: `.cursor/rules/*.mdc` with `description`, `globs`, `alwaysApply` (Always / Auto-attached / Agent-requested / Manual); plain `.md` there is ignored; **also reads `AGENTS.md` incl. nested** — so `AGENTS.md` alone covers Cursor.
- **Plugins**: `.claude-plugin/marketplace.json` (`name`, `owner{name,email,url}`, `plugins[]{name, source, description, version, skills, agents, commands, hooks, mcpServers, lspServers, strict, defaultEnabled}`; sources: relative path, `github`, `url`, `git-subdir`, `npm`, `archive`, `command`); users run `/plugin marketplace add owner/repo`, `/plugin install name@marketplace`; validate with `claude plugin validate .`. `claude plugin eval` / `/skill-doctor` exist in the current CLI but the docs page (`/docs/en/plugin-eval`) was **not fetchable (404)** in this session — **[unverified]** details; the anthropics/skills repo has no `evals/` convention either. Practical eval = a `tests/skills/` folder of prompt→expected-outcome fixtures run through `claude -p` in CI (or Codex `exec`), graded by a script; treat like snapshot tests.
- **MCP servers shipped by libraries / `context7.json`**: publishing docs to Context7 (`context7.json`) and a `llms.txt` are the low-cost defaults; shipping your own MCP server (e.g. `aiommbot-mcp` exposing "list routers/filters/actions in this bot") is only worth it when the library has runtime introspection that docs cannot express.

**AI contribution policies — spectrum (all primary):**
- **Ban**: Gentoo (Council, 2024-04-14; copyright, quality — "plausibly looking but meaningless content" —, ethics; revisable). NetBSD commit guidelines: LLM output "is presumed to be tainted code, and must not be committed without prior written approval by core".
- **Disclose + own it**: curl (`/dev/contribute.html`, "On AI use in curl"): must reveal AI use in security reports and double-check findings; PRs may use AI but "if someone can spot that the contribution was made with the help of AI, you have more work to do".
- **Allow code, forbid AI-written communication, require a human who understands it**: Astral `AI_POLICY.md` (linked from ruff `CONTRIBUTING.md`, "PRs not following it will be closed"): AI for coding OK, contributor stays responsible; "AI should not be used to generate comments when communicating with maintainers"; issues/PR bodies/replies "in your own words"; "we require a human in the loop who understands the work produced by AI"; "we do not allow autonomous agents to be used for contributing"; AI context allowed only in quote blocks with human explanation; non-native speakers may translate (native text + AI translation in a quote block). django-modern-rest `.github/AI_POLICY.md` is a near-verbatim adoption plus "wemake-services will block any users that abuse our AI policy" — while the same project ships an agent skill and "AI prompts for every breaking change" in its changelog.

**A balanced policy for a project that *wants* agent-assisted development (copyable):**
1. Agents welcome for code, tests, docs, refactors; **a named human owns every PR** and must be able to explain every line on request.
2. Disclose tooling in the PR template (`AI-assisted: yes/no; agent: …; what was reviewed by hand`).
3. Communication with maintainers is human-written; AI drafts only in quote blocks.
4. No unattended autonomous PRs from bots; agent-produced PRs must pass the *same* gates (ty, ruff, import-linter, coverage, `towncrier check`) and include the human's review notes.
5. Ship the guidance agents need: `AGENTS.md` (+`CLAUDE.md` importing it), `.agents/skills/` for the library's own usage patterns (routing, testing helpers, migration), `.claude/rules/*.md` path-scoped, `llms.txt`/`context7.json`.
6. Anti-slop gates: `typos`, `deptry`, docs snippets executed, PR size limits, "no drive-by reformatting", "no new abstractions without a caller".
7. Maintainers may close/hide AI-generated issue text; repeated abuse → block.

**Recommendation for our library:** commit `AGENTS.md` + `CLAUDE.md` (`@AGENTS.md`), `.agents/skills/<lib>-{usage,testing,migrate}/SKILL.md` symlinked into `.claude/skills/`, `.claude/rules/` path-scoped rules, `.claude-plugin/marketplace.json` exposing those skills, `llms.txt`, `context7.json`, and an `AI_POLICY.md` modelled on Astral's with the "agents welcome, human owns it" additions above.


## 7. Async runtime choices

- **asyncio vs anyio**: anyio **4.14.2** (Py ≥3.9, 3.15 supported; trio ≥0.31; `TaskGroup.start_soon()` now returns a `TaskHandle`; async `itertools`). faststream depends on `anyio>=4,<5` for backend neutrality. For a Mattermost/HTTP+WebSocket bot framework the extra trio backend buys little; stdlib asyncio 3.13+ (`TaskGroup`, `timeout()`, `Queue.shutdown`, `eager_task_factory`, 3.14 `ps/pstree` introspection) is sufficient and keeps the dependency graph minimal. Use anyio only if you already need its structured-concurrency primitives (`CapacityLimiter`, `to_thread.run_sync` with limiter, memory object streams) — and if so, use it *internally* without exposing it in the public API.
- **uvloop 0.22.1 (2025-10-16)**: cp313/cp314 + **cp314t wheels**, "2–4x faster", Linux/macOS only. **winloop** is the maintained Windows fork (`winloop.install()`, ~5x over Proactor). Make both optional extras (`[speed]`), never hard deps.
- **HTTP clients**: **aiohttp 3.14.3 (2026-07-22)**, Py ≥3.10, free-threading support since 3.13.0, client middlewares, Digest auth, zstd; 4.0 removals scheduled (`BasicAuth`/`auth` params). **httpx: latest is still 0.28.1 (2024-12-06)** per PyPI — 21 months without a release, 1.0 not shipped; treat as feature-frozen. **niquests** (requests fork on urllib3.future): HTTP/1.1/2/3, sync+async, multiplexing, DoH/DoQ, OCSP, WebSocket/SSE, OpenSSF badge; small team. For a library that streams WebSocket events and posts to a REST API, **aiohttp** is the pragmatic default (WS client + HTTP in one actively-maintained dependency); abstract it behind a `Protocol` so httpx/niquests can be swapped.
- **Event decoding: msgspec vs pydantic v2**. msgspec **0.21.1 (2026-04-12)**, Py ≥3.10, cp314t wheels, JSON/MessagePack/YAML/TOML; claims decode+validate JSON "faster than orjson can decode it alone", Struct ops 5–60x faster than dataclasses/attrs, tagged unions via `tag`/`tag_field`, `frozen`, `gc=False`, `array_like`, `omit_defaults`. pydantic **2.13.4 (2026-05-06)**: 3.14 supported since 2.12, experimental free-threading since 2.11, `pydantic-core` merged into the main repo in 2.13; richest ecosystem (settings, JSON Schema, FastAPI). Rule: **msgspec `Struct` for the hot path** (inbound WebSocket events, API responses — tagged union on `event` field) and **pydantic for user-facing config/settings/dialog schemas**; never both on the same object. Own benchmarks are mandatory before claiming numbers (write them with `pytest-benchmark`/`pytest-codspeed`).
- **orjson**: Py 3.10–3.15, "10x json" encode / ~2x decode, native dataclass/datetime/UUID; no PyPy, no subinterpreters, free-threading "eventually". Only needed if you *don't* use msgspec's encoder.
- **Retries**: tenacity remains the engine; **stamina 26.1.0** is the opinionated wrapper (retry only on given exceptions, exp. backoff + jitter, attempts *and* time caps, async/trio, typed decorators, Prometheus/structlog/OTel instrumentation hooks) — use stamina in the library, expose its `on=`/`attempts=` knobs.
- **Circuit breakers**: **purgatory** (sync+async factories, in-memory + Redis storage, state-change hooks, fully typed, docs moved to GitHub Pages) is the maintained choice; **aiobreaker** is stale — **[unverified]** last release. A framework can also ship a tiny Protocol-based breaker and adapt purgatory as an extra.
- **Logging**: structlog **26.1.0** documents `ProcessorFormatter` + `foreign_pre_chain` precisely so that stdlib-logging libraries render identically next to structlog apps. Libraries should use **stdlib `logging` with a `NullHandler`** and structured `extra=` dicts; do not depend on structlog. (Explicit "for library authors" wording is not on the fetched pages — **[inference from ProcessorFormatter design]**.)

**Recommendation for our library:** stdlib asyncio (3.13+), aiohttp behind a `Protocol`, msgspec Structs with tagged unions for events, pydantic only for settings/user schemas, stamina for retries, purgatory adapter as `[resilience]` extra, `uvloop`/`winloop` as `[speed]` extra, stdlib logging with `NullHandler`.


## 8. Observability for libraries

- **OpenTelemetry pattern**: depend on `opentelemetry-api` only (**1.44.0, 2026-07-16**, Py ≥3.10) — "unless your application imports the OpenTelemetry SDK, your instrumentation does nothing"; obtain `Tracer`/`Meter` from global providers with library name+version; follow semantic conventions; pin the *earliest* compatible API (`>=1.x`) to avoid conflicts; test with in-memory `SpanProcessor`/exporters. OTel docs even suggest keeping instrumentation in a separate package.
- **Messaging semconv** (still *Development* status, gated by `OTEL_SEMCONV_STABILITY_OPT_IN`): span name `{messaging.operation.name} {destination}`; operation types `create|send|receive|process|settle`; required `messaging.system`, `messaging.operation.name`; plus `messaging.destination.name`, `messaging.message.id`, `messaging.batch.message_count`, `error.type`; correlate producer/consumer with **span links** by default. A chat bot maps naturally: `messaging.system="mattermost"`, `process <channel>` CONSUMER spans per inbound event, `send <channel>` PRODUCER spans per post.
- **Prometheus**: `prometheus-client` is the de-facto standard, but it is process-global registry state — as a *library* keep an `Observer` Protocol + `NoopObserver` default and put `PrometheusObserver` behind an extra (this is exactly our BO observability standard).
- **faststream precedent (0.7.5)**: core deps only `fast-depends[pydantic]`, `typing-extensions`, `anyio<5`; extras `otel = ["opentelemetry-sdk>=1.24.0,<2.0.0"]` and `prometheus = ["prometheus-client>=0.20.0,<0.30.0"]`, brokers each an extra (`rabbit`, `kafka`, `nats`, `redis`, `mqtt`), `cli`. Note faststream pins the **SDK** in its extra (needed for its middleware helpers); a leaner library keeps `opentelemetry-api` as a *core* dep (it's tiny and no-op) and puts the SDK only in tests.

**Recommendation for our library:** core dependency `opentelemetry-api>=1.30,<2`; spans/metrics via the API following messaging semconv (`messaging.system="mattermost"`); Protocol-based observers with Noop defaults; `[prometheus]` extra with `prometheus-client`; `[otel]` extra only for optional SDK-based helpers/exporters.


## 9. Plugin/extension architecture

- **Entry points** (packaging spec): `[project.entry-points."aiommbot.plugins"] name = "pkg.module:object"`; discovered with `importlib.metadata.entry_points(group="aiommbot.plugins")`; groups are dotted identifiers, names case-sensitive. Zero-dependency, works with any installer, standard for third-party plugin discovery.
- **pluggy 1.6.0 (2025-05-15)**: `HookspecMarker/HookimplMarker("project")`, `PluginManager.load_setuptools_entrypoints(group)`, `firstresult`, new-style `wrapper=True` generators, `tryfirst/trylast`, `historic=True` hooks (late registrants replay past calls — useful for "on_startup" style hooks). **No native async hook support** — hookimpls returning coroutines must be awaited by the caller; pytest/tox/datasette prove the model, but for an async event framework a **Protocol-based, explicitly-async extension point** is cleaner.
- **Protocol-based extension points + optional-dependency guards**: define `class StorageBackend(Protocol)`, `class Observer(Protocol)`, `class HttpClient(Protocol)`; ship in-memory/Noop defaults in core; put real backends behind extras with a guard that raises a typed `MissingExtraError("install aiommbot[mongo]")` at *construction*, not import. `deptry` keeps extras honest; `[tool.uv] conflicts` declares mutually exclusive extras.
- **Extras design**: small core (`msgspec`, `aiohttp`, `opentelemetry-api`, `typing-extensions`); extras `mongo`, `redis`, `prometheus`, `otel`, `speed`, `cli`, `all` (composed). Groups (`dev`, `lint`, `docs`, `typing`) are for contributors and never published.
- **Django as inspiration**: `INSTALLED_APPS` → explicit ordered list of plugins; `AppConfig` (`name` unique dotted path, `label`, `default`) → a `Plugin` object with identity + metadata; three-phase `django.setup()` (import configs → import models → `ready()`) → **import plugins → register handlers/routers → `ready(app)`**; `ready()` caveats transfer 1:1 (no I/O, idempotent — "may be called more than once in tests", `dispatch_uid`-style dedupe); registry API `apps.get_app_config()/is_installed()` → `bot.plugins["name"]`. Django signals (`Signal.connect(receiver, sender, weak, dispatch_uid)`, `send` vs `send_robust`, **async `asend`/`asend_robust` since 5.0**, receivers `(sender, **kwargs)`) are a good model for lifecycle/cross-plugin events, with the docs' own warning: prefer direct calls when both sides are yours. The main thing *not* to copy: implicit global registry populated by import side effects — make registration explicit on the composition root (`Bot(plugins=[...])`) so agents and type checkers can see it.

**Recommendation for our library:** explicit `Bot(plugins=[...])` composition root with a typed `Plugin` protocol (`name`, `setup(bot)`, `ready(bot)`, `shutdown(bot)`), entry-point group `aiommbot.plugins` for *discovery* of third-party plugins (opt-in `Bot.discover_plugins()`), Protocol-based backends behind extras with construction-time guards, an async `Signal` for lifecycle events; skip pluggy.
